# Паттерны элементов — база для нейросети

Что надо знать, прежде чем делать или править узор элемента. Стиль подробно — `СТИЛЬ.md`.

## 1. Что такое паттерн

У каждого элемента (Огонь, Вода, Взрыв…) есть свой узор. Он лежит фоном на всех плашках элемента:
ячейки списков, слоты крафта, справочник, узел карты рецептов. Один узор на элемент, на все фоны.

## 2. Формат маски

- Файл `out/p_<Элемент>.png` (имя элемента по-английски, как ключ в коде: `p_Explosion.png`).
- **1024×1024**, RGBA. RGB = белый (255), **рисунок — в альфе**.
- Альфа = яркость узора в игре: 0 — тёмный корпус, ~140 — средний тон («поле», FILL = 0.55),
  255 — полный цвет элемента (яркая линия).
- Игра красит белую маску цветом элемента. Слишком тёмные цвета (Обсидиан, Уголь, Грязь)
  осветляются к белому (`Theme.PatternTint`), так что превью рисовать осветлённым цветом.

## 3. Как игра показывает узор (важно для композиции)

- **Без повторения плиткой.** Из текстуры вырезается одно окно размером с ячейку, от левого
  верхнего угла (`offset`, обычно 0,0). Мелкая ячейка видит только верхний левый кусок
  (минимум ~230 px по высоте, `minRect`), большая — почти всю картинку.
- Поэтому важна **вся площадь** 1024×1024: в больших окнах видно всё сразу. Скопированные
  куски, сетка 2×2, «нижняя половина = верхняя» бросаются в глаза.
- Верхний левый угол должен сам по себе узнаваться — это то, что видит игрок в мелких ячейках.
- Код: `src/StarterPlayer/StarterPlayerScripts/UIThemeButtons.luau`, таблица `Theme.patterns`
  (`image` — id картинки на Roblox, `size`, `offset`, `minRect`, `transparency`, иногда `color`,
  `density`), функции `fitPattern`, `Theme.Pattern`.

## 4. Стиль (кратко; полностью — `СТИЛЬ.md`)

- **Идеал — Металл** (тёмные плиты, тонкие яркие заклёпки и царапины). Ещё образец — Камень.
- Плоская графика, 2–3 тона: тёмный фон, средняя заливка, яркая линия. **Никакого 3D-рендера**,
  бликов, градиентного объёма, «куполов».
- Тёмного 60–85% площади, яркого ≤ 20%. Яркое — **тонкие неровные линии** (2–4 px на 1024),
  а не заливки.
- **Не мультяшно.** Автор считает мультяшным: языки пламени-наклейки, клипарт-завитки,
  гладкие надутые капли, ячейки с толстой одинаковой обводкой, комиксные зигзаги, иконки волн.
  Не мультяшно: горошек (Вспышка, Снег), мягкие плиты (Землетрясение), комиксный взрыв,
  листья (Растение), кирпичи, иконки алмазов, рваный камуфляж (Пыль), пузыри с деталями.
- Элемент узнаваем и **не похож на соседей** (Пыль / Кислород / Землетрясение / Камень).
- Исключения: Огонь — тёмные языки на светлом поле (так решил автор). Вода, Лужа, Обсидиан,
  Уголь оставляют лёгкий объём.

## 5. Чего автор НЕ хочет

- **Процедурных перерисовок с нуля** (векторы, шум, генераторы). Проверено: 11 версий Огня
  проиграли одной картинке нейросети автора. Лучше всего — картинка от нейросети **в стиле
  исходника**, агент делает только техническую доводку.
- **Швов** — ни видимой границы склейки, ни линий, обрывающихся в воздухе («стык»).
- **Грубых копий**: кусок картинки, вставленный ещё раз рядом (было у Взрыва, Смога, Пыли).
  Повтор по смыслу (плиты Металла, кладка Камня) — нормально.
- **Обрезать картинку, чтобы спрятать шов.** Правильно — расширенная картинка без стыка.
- Мелких правок, которые в игре не видно.

## 6. Как работать с автором

- Новый дизайн или перерисовка — **сразу 3 разных варианта (А/Б/В) на одном листе**,
  дальше дорабатывать только выбранный.
- Чистая починка шва — **один результат**, без вариантов.
- Автор одобрил («оставляем») — сохранить и сразу брать следующий элемент, не спрашивая.
  «Оставляем, но сделай лучше» — это НЕ одобрение: доделать, показать и ждать.
- Показывать сравнение «было / стало» в цвете элемента, как в игре.
- Отвечать коротко, по-русски, без лишних вопросов.

## 7. Конвейер

1. Исходник — в `Исходники/` (картинки автора или нейросети).
2. Маска — в `out/p_<Элемент>.png`:
   - `build_patterns.py` строит маски по таблице `CFG` (режимы `line`, `shape`, `photo`, `bokeh`).
   - Маски, сделанные руками/из готовых картинок автора, перечислены в множестве `HAND` —
     скрипт их не перезаписывает. Новую ручную маску — добавить туда.
   - Готовая картинка уже в стиле маски (тёмный фон, серое поле, белые линии) переводится
     прямо: яркость → альфа, серое поле → ~140, белое → 255, ресайз в 1024×1024.
3. Проверка: доля тёмного/яркого, швы по обеим осям, копии кусков (скрипты
   `Исследование дублей/dupscan.py`, `dupbox.py`), вид в цвете элемента.
4. Загрузка в Roblox через MCP Studio (`upload_image`): нужен `studio_id`
   (`list_roblox_studios`); ссылки на GitHub не принимаются — раздать файлы с localhost
   (`python -m http.server`); не больше ~4 картинок за раз, иначе таймаут.
5. Новый id и `size` — в `Theme.patterns` (`UIThemeButtons.luau`). Код правится только
   файлами в `src/`, не через Studio.
6. Коммит и пуш — все действия идут через GitHub.

## 8. Если делаешь картинку для узора (подсказка генератору)

> Плоская графическая текстура 1:1 для фона игровой плашки. Почти чёрный фон, средне-серые
> формы, тонкие неровные белые контурные линии, как от руки. Без 3D, без бликов, без
> градиентов, без мультяшных наклеек. Сплошной узор по всей площади, без центральной
> композиции, без повторяющихся кусков, без швов по краям. Тема: <элемент>.
