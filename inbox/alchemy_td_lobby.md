# ТЗ — лобби, сохранение, уран

Правила работы — в `RULES.md`. Текущее состояние — в `STATE.md`.

Цифр здесь нет: размеры наград и прочий числовой баланс живут в таблицах кода, а не в вики.

## Задача

Замкнуть игровой цикл: сейчас забег кончается и всё обнуляется. Нужно, чтобы прогресс
сохранялся между сессиями, а игрок попадал в уровень из лобби и возвращался обратно.

Уран в этой версии только **начисляется и сохраняется**. Магазин рецептов — отдельное ТЗ.

## Порядок работ

Строго последовательно, каждый пункт — отдельная задача с проверкой.

1. Сохранение (DataStore)
2. Начисление урана
3. Лобби и переход в уровень
4. Выбор уровня

---

## 1. Сохранение

**Что сохраняется между сессиями:**

| Данные | Описание |
|---|---|
| Уран | внешняя валюта |
| Открытые рецепты | список элементов, доступных к крафту |
| Пройденные уровни | какие открыты, какие пройдены |
| Лучший результат по уровню | максимальная достигнутая волна |

**Что НЕ сохраняется** — всё, что живёт внутри забега: эссенция, элементы в инвентаре,
построенные турели, их позиции. Это уничтожается в конце забега по дизайну.

**Требования:**

- Использовать **ProfileStore** (или аналогичную библиотеку с session-locking), не голый
  DataStore. Наивная реализация теряет прогресс при вылете и при заходе с двух устройств.
- Данные грузятся при входе игрока, сохраняются при выходе и периодически по таймеру.
- Если данных нет — создаётся профиль по умолчанию: урана нет, открыты только базовые
  рецепты, открыт первый уровень.
- Место должно быть опубликовано и включена Studio Access to API Services, иначе DataStore
  не работает в Studio.

**Проверка:** заработать уран, выйти, зайти — уран на месте. Проверить, что при первом
входе профиль создаётся без ошибок.

## 2. Начисление урана

Уран даётся **за достижение нового**, не за время. Иначе игрок находит лёгкий забег и
гриндит его повторением.

**За что начисляется:**

| Событие | Условие |
|---|---|
| Первое прохождение волны | каждая волна уровня — только первый раз |
| Новый рекорд на уровне | зашёл дальше, чем раньше |
| Первое прохождение уровня | разовая награда, крупнее остальных |
| Первое убийство нового типа жука | по одному разу за тип |

Повторное прохождение уже пройденного урана не даёт — только удовольствие и тренировку.

**Требования:**

- Размеры наград — в таблицу, не в код.
- Факт «уже получено» хранится в профиле игрока, проверяется на сервере.
- При начислении показывать игроку, за что именно дали.

**Проверка:** пройти уровень, получить уран. Перепройти — урана не дать. Зайти дальше
прежнего рекорда — дать за новые волны.

## 3. Лобби и переход в уровень

**Одна комната в том же плейсе, без отдельных серверов и телепортов.**

- Игрок появляется в лобби при входе в игру.
- В лобби есть точка входа в уровень — интерактивный объект (ProximityPrompt).
- При старте уровня арена готовится: очищается от построек предыдущего забега, сбрасывается
  эссенция, инвентарь элементов, счётчик прорывов.
- По окончании забега (победа или поражение) игрок возвращается в лобби.
- В лобби видно: уран, открытые уровни, лучший результат по каждому.

**Требования:**

- Переход между лобби и ареной — смена состояния, а не загрузка. Игрок перемещается,
  арена пересобирается.
- Состояние забега (эссенция, инвентарь, постройки) создаётся при старте и уничтожается
  при возврате в лобби.
- Если игрок вышел посреди забега — при следующем входе он в лобби, забег не
  восстанавливается.

**Проверка:** зайти в игру → оказаться в лобби → войти в уровень → проиграть → вернуться в
лобби → войти снова, арена чистая.

## 4. Выбор уровня

- Уровни идут подряд: пройденный открывает следующий.
- Пройденный уровень можно перепройти в любой момент.
- В лобби — список уровней с отметкой: открыт / пройден / лучший результат.
- Непройденные и неоткрытые видны, но недоступны.

Сейчас уровень один — обучающий. Структура должна быть готова к добавлению следующих
строкой в таблицу.

**Проверка:** пройти первый уровень, убедиться, что второй помечен как открытый (даже если
его содержимого ещё нет).

## Технические требования

Без изменений: логика на сервере, RemoteEvent с проверкой, данные в ModuleScript,
расширение строкой в таблице.

Дополнительно: **список уровней — в таблице**, с полями «номер, название, состав волн,
карта». Добавление уровня не должно требовать правки логики.

## Не входит в это ТЗ

- Магазин рецептов за уран — отдельное ТЗ
- Второй уровень и его содержимое
- Визуал лобби — сейчас достаточно функциональной комнаты
