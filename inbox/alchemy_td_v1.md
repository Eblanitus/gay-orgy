# Алхимия + Tower Defense — ТЗ первой версии (вертикальный срез)

## Цель этой версии

Проверить одну гипотезу: интересно ли играть, когда **башня задаёт форму урона, а элемент задаёт его содержание**.

Всё, что не проверяет эту гипотезу, в первую версию не входит.

## Чего в v1 НЕТ (важнее списка того, что есть)

- Нет сохранения прогресса. Раунд начинается с нуля. DataStore не используется вообще.
- Нет монетизации, геймпассов, валюты за робуксы.
- Нет моделей и анимаций. Всё — примитивные Part с цветами.
- Нет красивого интерфейса. Кнопки и текст, без картинок.
- Нет мультиплеерного соревнования. Один игрок на сервере.
- Нет случайных волн, ребёртов, уровней башен.

## Ядро

### Базовые элементы (4)

Доступны сразу, бесконечны:

| Элемент | Цвет |
|---|---|
| Огонь | оранжевый |
| Вода | синий |
| Земля | коричневый |
| Воздух | белый |

### Скрещивания (6)

Игрок соединяет два элемента и получает новый. Открытый элемент остаётся доступен до конца раунда.

| Рецепт | Результат |
|---|---|
| Огонь + Земля | Лава |
| Вода + Воздух | Лёд |
| Огонь + Воздух | Молния |
| Вода + Земля | Кислота |
| Огонь + Вода | Пар |
| Земля + Воздух | Песок |

Порядок элементов в рецепте значения не имеет.

### Свойства урона

У каждого элемента набор признаков, а не отдельная логика:

| Элемент | Тип урона | Урон | Особое |
|---|---|---|---|
| Огонь | по времени | 3/сек, 4 сек | — |
| Вода | удар | 8 | замедление 20%, 2 сек |
| Земля | удар | 15 | — |
| Воздух | удар | 5 | скорострельность +50% |
| Лава | по времени | 6/сек, 5 сек | урон по площади 8 |
| Лёд | удар | 6 | замедление 60%, 3 сек |
| Молния | удар | 12 | бьёт до 3 целей цепочкой |
| Кислота | по времени | 4/сек, 6 сек | игнорирует броню |
| Пар | по времени | 2/сек, 3 сек | по площади, замедление 30% |
| Песок | удар | 7 | по площади 5 |

Цифры — заготовка для баланса, менять свободно.

### Башни-сосуды (2)

Нейтральны, урона без элемента не наносят.

**Баллиста** — одиночная цель, 1 выстрел в секунду, радиус 30. Доставляет элемент точно и целиком.

**Луч** — непрерывный урон одной цели, тикает 4 раза в секунду по 1/4 урона, радиус 20. Хорош против регенерации, плох против толпы.

Элемент накладывается на пустую башню и снимается обратно.

### Свойства врагов (3)

Не элементы, а сопротивления. Один враг может иметь несколько.

| Свойство | Механика | Чем контрится |
|---|---|---|
| Броня | −70% урона типа «удар» | урон по времени, кислота |
| Регенерация | +5 HP/сек, останавливается на 2 сек после любого урона | непрерывный урон (Луч) |
| Толпа | по 1 HP каждый, идут по 15 штук | урон по площади |

### Волны (5, фиксированные)

| Волна | Состав | Проверяет |
|---|---|---|
| 1 | 5 обычных, 30 HP | базовое понимание |
| 2 | 8 обычных, 40 HP | нужна вторая башня |
| 3 | 4 с бронёй, 60 HP | удар не работает, нужен урон по времени |
| 4 | 15 в толпе, 1 HP | нужен урон по площади |
| 5 | 3 с регенерацией и бронёй, 100 HP | нужен Луч + кислота |

Между волнами пауза 15 секунд на перестройку.

## Технические требования

- **Вся логика урона, здоровья, волн и открытия элементов — только на сервере.** Клиент отправляет намерение («поставить башню тут», «наложить элемент»), сервер проверяет и решает.
- Каждый RemoteEvent проверяет на сервере: хватает ли ресурсов, открыт ли элемент, допустима ли позиция. Ничего не принимать от клиента на доверии.
- Данные элементов, башен и волн — в отдельных ModuleScript с таблицами, а не внутри логики. Расширение должно быть добавлением строки в таблицу.
- Структура: ServerScriptService для логики, ReplicatedStorage для общих таблиц данных, StarterPlayerScripts для интерфейса.

## Критерий успеха

После пяти волн должно быть желание переиграть и попробовать другую сборку. Если нет — проблема в схеме, а не в количестве контента, и добавлять элементы бессмысленно.
