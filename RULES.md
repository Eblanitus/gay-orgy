# RULES — правила работы с проектом

Читать в начале работы. Действует для любого агента, который правит этот проект.

## Документы

| Файл | Когда читать |
|---|---|
| история задач (`git log`) | при поиске причины поломки: `git log --grep`, `git log -- <файл>` |
| `Устаревшие документы/CHANGELOG.md` | **никогда целиком** — только `grep`, если причина поломки старше 24.09.2026 |
| дизайн-документы | только тот, что относится к текущей задаче |

Дизайн-документы — папка `ВИКИПЕДИЯ/`, по одному файлу на тему. Тема — слово в имени
файла (`alchemy_td_<тема>_v<версия>.md`), искать по нему: `ls ВИКИПЕДИЯ`.

- `recipes` — дерево рецептов
- `effects` — свойства элементов: урон снаряда, модификаторы турели
- `debuffs` — эффекты, которые висят на жуке
- `enemies` — виды жуков
- `enemy_mechanics` — механики жуков (броня)
- `towers` — турели: внешний вид, работа, по каким целям бьют
- `currencies` — валюты
- `location` — локация бункер
- `art_style` — стиль моделей: материалы, цвета, акцент, формы
- `game_style` — стиль игры (нео-скайфай): чем отличается от обычного футуризма, три мира, детализация лоу-поли, сквозные правила, стоп-лист

**Ссылок на документы вики нет нигде.** Ни код, ни правила, ни сами документы не
называют файл вики по имени, разделу или шагу — иначе каждое обновление документа
ломает ссылки. Нужно сказать, откуда правило, — «по вики», без имени файла.

**В вики нет цифр.** Числовой баланс живёт в таблицах кода, документы описывают только
смысл механики. Не дописывать в них числа обратно.

**Версия в имени файла совпадает с версией в заголовке документа.** Документ получил
новую версию — файл переименовывается сразу, в том же коммите.

**Версия в имени файла (`_v2`, `_v3.1` и т.д.) относится только к этому документу**
и никак не связана с версиями других документов. Один файл может годами оставаться
`v2` и не меняться, а другой — дойти до `v5`. Не пытаться синхронизировать номера
версий между разными документами и не делать выводов о свежести одного файла по
номеру версии другого.

Отработавший документ переезжает в папку `Устаревшие документы/`.

## История задач

С 24.09.2026 проект в Git, история задач — в **сообщениях коммитов**, отдельный файл не ведётся.
Старый `CHANGELOG.md` (задачи #1–#232) — архив в `Устаревшие документы/`, **в него больше не
дописывать**. Записи в архиве идут не строго по порядку — самый большой номер искать
`grep`, а не по первой строке.

Номера задач в Git продолжаются с **#233**. Первые git-задачи 24.09.2026 (#233 бэкап —
#242) в заголовках коммитов записаны старыми номерами #196–#204 и #233 — там номер
в заголовке на 37 меньше настоящего (коммит «#233 — нумерация» — это #242). Настоящие
номера: бэкап #233, Rojo #234, архив CHANGELOG #235, ползунок музыки #236, start.bat #237,
паттерны #238, Инжектор #239, разбивка файлов #240, уборка ServerStorage #241, нумерация #242.
Следующий номер — последний в истории плюс один: `git log --oneline --grep "^#" -1`
(фиксированное число здесь не держать — оно сразу устаревает).

## После каждой задачи

1. Сделать коммит. Заголовок: `#номер — суть задачи`. Тело — как раньше запись в CHANGELOG:
   что сделано, какие файлы затронуты, что **проверено** и что **не проверено**.
2. Запушить на GitHub.

## Чего не делать

- **Не читать файлы, не относящиеся к текущей задаче.** Проект большой, чтение
  впустую съедает контекст и лимиты.
- **Не читать архивный `CHANGELOG.md` целиком.** Он на тысячи строк и в контекст не влезает.
- **Не лезть в системные журналы Windows, логи Studio и не чинить падения Studio.**
  Это не задачи проекта.
- **Не досыпать ресурсы при тестах.** Обход экономики маскирует ровно ту проблему,
  которую нужно увидеть.
- **Не читать "C:\Users\user\Contacts\Устаревшие документы" - если не требуется в задаче.**
## Технические правила проекта

- **Вся игровая логика — на сервере.** Клиент отправляет намерение, сервер проверяет
  и решает. Ничего не принимать от клиента на доверии.
- **Данные — в таблицах ModuleScript, не в коде.** Новый элемент, жук или турель
  должны добавляться строкой в таблицу, а не правкой логики.
- **Цифры баланса — в таблицах.** В коде констант не держать.
- Структура: `ServerScriptService` — логика, `ReplicatedStorage` — общие данные,
  `StarterPlayerScripts` — клиент и интерфейс.
